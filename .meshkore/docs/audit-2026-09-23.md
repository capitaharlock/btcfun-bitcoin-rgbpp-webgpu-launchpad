# Technical audit, 23 September 2026

An external review of the repository at `25f3709`, with reproductions. Every
finding was reproduced locally before being acted on, and none was dismissed as
theoretical. This file records what each one was, what was done, and what is
still open — so a later reader can tell a closed finding from a deferred one
without reading commit messages.

The reproductions live in the operator's `tmp/` (untracked): `audit-repros.mjs`
drives the real modules through a Vite SSR loader and writes `audit-repros.json`.
They use deterministic throwaway keys, touch no wallet, and make no network call.

## What the audit established about the project as a whole

Two framing corrections that matter more than any single defect:

**There is an implementation, and it is not the target protocol.** `apps/web`
holds a wallet, a CPU/WebGPU miner, a signed ledger, an offer book and an index.
There is no Rust, no CKB script, no RGB++ SDK — so TypeScript quality and
composition can be judged, and mastery of CKB-VM or RGB++ settlement cannot be
claimed. See [capabilities.md](capabilities.md), added in response.

**The prototype's trust boundary is not the architecture's.** Two conflicting
signed histories are equally valid to a verifier; the reserve address has no
known key and is not redeemable; the index authenticates authors, not events.
These are stated per screen and now stated at each definition too.

## The three that were nearly invisible

Worth recording, because they are the kind a test suite does not catch by
growing.

**AUD-07 — the fee.** `selectCoins` took an output *count*. An OP_RETURN with
an 80-byte memo is a 92 vB output where a P2WPKH is 31, so a one-in two-out
payment with a memo estimated 141 vB and a node measured 233: 0.605 sat/vB
against a requested 1. Every ticket and every offer fill carries a memo, so this
was the normal path. The unit tests were thorough about `selectCoins` and never
looked at the finalised transaction — the boundary the bug lived on.

**AUD-11 — settlement.** Status came from a memo prefix on any transfer. One
atom closed a five-token sale with no payment recorded. The module's header
correctly warned that the swap is not atomic, which is a real and larger
limitation; that warning is what made a false positive about the leg that *did*
happen easy to overlook.

**AUD-13 — rounding.** The comment declared `floor(M × (1 − p))`; the code
computed `M − floor(M × p)`, which rounds the other way. One atom, invisible in
any property test that checks monotonicity and telescoping — both of which hold
under either rounding. It surfaced only against an independent reference, which
is why `emission.test.ts` now carries one that avoids fixed point entirely.

## Still open, deliberately

- **Economics** (`AUD-03`): `E1`–`E5`. The `§4.3` cap is implemented and labelled
  a candidate; genesis, admission, holdbacks, concurrency and exits are unspecified.
- **Settlement** (`AUD-05`, and the atomicity gap behind `AUD-11`): `V3`, `V8`,
  `V9`. SPV evidence, an accepted Bitcoin clock, admission completeness, and
  RGB++ single-use seals for atomic swaps.
- **Custody** (`AUD-15`): whether a self-custodied browser wallet is the right
  design before real funds, or whether an external wallet should carry it. The
  gate is `SH7`.
- **Pari-mutuel allocation within an epoch** (`AUD-10`'s wider half): the current
  rule is sequential and first-claim-takes-the-budget, which is a single-participant
  model, not a multi-participant one. Specified by `E3`, not by this fix.

## What changed in how the code is written

Two habits, recorded because they are the general lesson rather than the specific
bug:

**Validate at the boundary, in one place.** `AUD-09` and `AUD-14` were the same
mistake twice — a TypeScript cast standing in for a runtime check on JSON from
storage. There is now exactly one decoder (`lib/ledger/decode.ts`), it is
exhaustive over kinds at compile time, and `replay` calls it before it verifies
anything.

**Never name a thing more strongly than the code can support.** `verified` for a
checked signature, `settled` for an unmatched memo, "records verified" for a
replay that never saw a payment. Each was a single word, and each implied a
guarantee that did not exist.
